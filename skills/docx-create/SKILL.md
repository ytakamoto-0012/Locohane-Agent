# docx-create

A skill that generates a new Word document (`.docx`) from a JSON spec. Run `create_docx.py` to
get the result.

The document is generated by **passing a JSON string that the LLM itself builds as is to the `--data` argument**
(only if the user has prepared a JSON file in advance, you can also give its path with
`--data-file`). The same design as `create_pptx.py` of `pptx-create`.

On success it prints one line of JSON to stdout with exit code 0; on failure it prints an
error message to stderr with a non-zero exit code.

Call example:
```bash
python create_docx.py "C:\Users\me\report.docx" --data '{"blocks": [{"type": "heading", "text": "1. Overview", "level": 1}, {"type": "paragraph", "text": "This is the body."}]}'
```
The value of `--data` is a JSON string following the "JSON spec format" below. When the JSON gets long,
use `<output path.docx> --data-file <absolute path of the JSON spec file>` instead of `--data`
(always specify exactly one of `--data`/`--data-file`; specifying both or neither is an error).

## JSON spec format

```json
{
  "theme": "navy",
  "core_properties": {"title": "Report", "author": "Taro Yamada"},
  "page": {
    "size": "a4",
    "orientation": "portrait",
    "margin_cm": {"top": 2.5, "bottom": 2.5, "left": 3.0, "right": 2.5}
  },
  "header_text": "Confidential",
  "footer_text": "Sample Inc.",
  "page_number": true,
  "blocks": [
    {"type": "heading", "text": "1. Overview", "level": 1},
    {"type": "paragraph", "text": "Body text.", "bold": false},
    {"type": "callout", "text": "Important: the deadline is the end of next month."},
    {"type": "bullet_list", "items": ["Item A", "Item B", "Item C"]},
    {"type": "number_list", "items": ["Step 1", "Step 2"]},
    {"type": "table", "rows": [["Item", "Value"], ["Sales", "12 million yen"]], "header_row": true},
    {"type": "image", "path": "C:\\foo\\chart.png", "width_cm": 10},
    {"type": "page_break"}
  ]
}
```

All top-level keys can be omitted (specifying only `blocks` creates a minimal
document).

- `theme`: optional (default `charcoal`). Decides the heading text color, the colors of table header rows and
  the colors of `callout` all at once. See "Color themes" below.
- `core_properties`: optional. Sets `title`/`author` in the document properties.
- `page`: optional. `size` is `"a4"` (default) or `"letter"`. `orientation`
  is `"portrait"` (default) or `"landscape"`. `margin_cm` is the top/bottom/left/right
  margins (in cm; the default is 2.5cm top and bottom, 3.0cm left, 2.5cm right).
- `header_text`/`footer_text`: optional. Strings shown in the header/footer.
- `page_number`: optional, default `false`. `true` adds a page number field
  (`{PAGE}`, calculated automatically in Word) at the center of the footer.
  Depending on Word's settings, the field may be shown grayed out instead of an actual number such as `1`,
  but the correct page numbers appear when printing or converting to PDF
  (fields are calculated when Word opens the document).
- `blocks`: an array of the body elements in order from the top. The spec for each element's `type`
  is as follows.

### Color themes (theme)

8 kinds based on the Design Ideas (color palettes) of Anthropic's official pptx skill
(the same names and colors as `pptx-create`/`excel-edit`. To align the look of a set of materials,
specify the same `theme` name for xlsx/pptx/docx).

| theme | Main tone |
|---|---|
| `charcoal` (default) | Charcoal gray, a calm neutral tone |
| `navy` | Dark navy, a trustworthy business tone |
| `forest` | Deep green, evoking growth and the environment |
| `coral` | Navy + coral, bright and strong |
| `terracotta` | Terracotta, warm earth tones |
| `ocean` | A deep blue gradient tone |
| `teal` | Teal, a clean tone |
| `berry` | Berry color, calm and elegant |

### Each type of blocks

| type | Required keys | Main optional keys | Description |
|---|---|---|---|
| `heading` | `text` | `level` (default 1; 0 = Title, 1-9 = heading levels) | Heading paragraph. Drawn in the theme color + a Gothic font |
| `paragraph` | `text` or `runs` | `alignment` (`left`/`center`/`right`/`justify`; any other value or omission keeps the default left alignment without an error), `bold`/`italic`/`underline`/`color`/`font`/`size_pt` (take effect directly only when using `text`) | A normal paragraph. Use `runs` for a sentence mixing several formats |
| `bullet_list` | `items` (array of strings) | None | Bullets |
| `number_list` | `items` (array of strings) | None | Numbered list |
| `table` | `rows` (array of rows; each row is an array of cell strings) | `header_row` (if true, the first row is filled with the theme color in white bold) | Table. The number of columns follows the longest row |
| `callout` | `text` | `bold`/`italic`/`underline`/`color`/`font`/`size_pt` | An emphasis box paragraph with a thick theme-colored rule on the left + a light fill. For supplements and cautions |
| `image` | `path` (absolute path of the image file) | `width_cm`, `height_cm` (specifying only one keeps the aspect ratio) | Insert an image. The path must be the absolute path of an existing file |
| `page_break` | None | None | Page break |

For `runs` of `paragraph`/`callout` (`paragraph` only) and the direct keys, `text` is required, and you can specify
`bold`/`italic`/`underline` (booleans), `color` (an RRGGBB hex string such as `"FF0000"`),
`font` (a font name; Japanese font names such as Yu Mincho are also OK) and `size_pt`
(font size in pt). The default fonts are Yu Mincho for the body and
Yu Gothic for headings. In a document without Japanese text, the Latin letters use
Times New Roman (body) and Arial (headings) instead, so no font setting is needed for English documents.

Elements with an unknown `type` are skipped without an error, and that is recorded in the
`warnings` of the result (see below).

## Procedure

1. Build the JSON spec above from the user's request.
2. Run the command above.
3. If the output already exists it is overwritten without confirmation, so when it might
   overwrite an existing file, confirm with the user before running.
4. On success, tell the user `output_path`. If `warnings` is not empty,
   also tell them its content (that an unknown type was skipped, etc.).

## Output example

```json
{"output_path": "C:\\foo\\report.docx", "blocks_written": 8, "warnings": []}
```

## Edge cases

- An output extension other than `.docx`, an unparsable JSON string, an unsupported
  `theme` name, empty `table.rows`, or an `image.path` that does not exist
  all give an error message + exit code 1. Pass the content to the user as is.
- Specifying both `--data`/`--data-file`, or neither, unlike the above, is a usage error from the
  mutually exclusive required group of `argparse`, so the exit code is 2 (argparse's usage message
  is printed to stderr).
- If the output already exists it is overwritten without confirmation (the same behavior as `pdf-tools`/`pptx-create`).
  It is good to confirm with the user beforehand whether overwriting is OK.
- If the parent directory of the output does not exist, it is created automatically.
- Page numbers (`page_number: true`) use Word's "field" feature, so unless converted to PDF etc.,
  the numbers may not appear until the document is opened in Word once or the fields are updated (F9).
- If the dependency `python-docx` (import name `docx`) is not in the environment, it ends with
  `ModuleNotFoundError` and a non-zero exit code. In that case, prompt the installer to
  run `pip install python-docx`.

## Checking after generation, editing existing documents

To check the layout of the generated document as images, use `render_docx.py` of the `docx-render` skill
+ `analyze_image`. To partially edit an existing docx file, use `docx-edit`
instead of this skill (this skill is for creating new documents only and has no append mode like `--new`).
